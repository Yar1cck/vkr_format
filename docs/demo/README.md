# Демо-документы для защиты

Готовые `.docx`, на которых удобно показать работу сервиса. Лежат в
репозитории намеренно (в отличие от `tests/fixtures/*.docx`,
которые игнорируются git'ом и регенерируются на лету).

| Файл | Зачем | Что показывает |
|---|---|---|
| [01_minimal.docx](01_minimal.docx) | «Чистый» документ — почти без нарушений | golden-path: загрузка → быстрая обработка → почти пустой отчёт |
| [02_with_violations.docx](02_with_violations.docx) | Максимум типов нарушений в одной работе | весь спектр UI: подсветка, conflict review, snapshot history, manual_required |

## Демо-сценарий за 60 секунд

1. **Студент** → загрузить `02_with_violations.docx`.
2. Дождаться `done` (≈30 с — миграции, обработка, превью).
3. Открыть детали: видно список замечаний с подсветкой в PDF-превью.
4. На конфликте номера заголовка нажать «Исправить» → выбрать номер → отправить.
5. Открыть «История изменений» → откатить последнее действие.
6. **Логаут → войти как руководитель** (в другой вкладке) → видеть работу студента → approve/reject.
7. **Логаут → войти как админ** → `/admin/stats` показывает агрегаты.

## Если на защите что-то не так

- `docker compose restart api` — на 99% «не отдаёт превью» решается этим.
- `docker compose logs api worker | tail -50` — посмотреть последнее, что произошло.
