# Замер качества детектора заголовков (A-N1, ТЗ §7.9, Р-04)

Этот каталог содержит harness для замера precision / recall / F1 детектора
заголовков (`engine/detection.py`) на корпусе ВКР.

## Зачем

Все пороги в скоринговой модели (`heading_scoring.py`) — `10/6/3` для tier'ов,
`0.8/0.5` для `bold_ratio`, `100/200` для `length`, и т.д. — подобраны на
основе анализа реальных документов, но без формального замера. Без чисел в
дипломе нельзя сказать «алгоритм работает корректно» — только «работает на
тех документах, что я смотрел». Этот скрипт даёт измеримый ответ.

## Два режима

### 1. Manual (ручная разметка) — основной

Эталон — JSON с ручной классификацией каждого «интересного» абзаца. Даёт
настоящие precision/recall/F1 на реальных ВКР, в том числе на «грязных»
документах с потерянными стилями.

Формат разметки — см. `example_annotation.json`. Размечать **не нужно
каждый абзац**: для не упомянутых абзацев предполагается «не заголовок».
Это сильно ускоряет работу — обычно достаточно перечислить ~50–100
заголовков и несколько проблемных не-заголовков (lead-in списков,
выделенные термины), которые алгоритм мог бы ложно принять за заголовок.

### 2. Word-style baseline (без корпуса)

Эталон — `paragraph.style.name == "Heading N"` / `"Заголовок N"`. Работает
на любом docx без подготовки. Что измеряем: согласие нашего детектора с
native Word-разметкой на тех абзацах, где она есть. Это слабый baseline
(на «грязных» документах со сбитыми стилями он бесполезен — там и
heading-стилей нет, и абзацы помечены `Normal`), но даёт хоть какие-то
числа для упоминания в работе.

## Запуск

```bash
# Manual mode (есть корпус с разметкой)
python -m tests.quality.measure_heading_detection \
    --corpus path/to/docx_corpus/ \
    --annotations path/to/annotations.json \
    --output reports/heading_quality.json

# Word-style mode (без корпуса)
python -m tests.quality.measure_heading_detection \
    --corpus path/to/docx_corpus/ \
    --baseline word-style \
    --output reports/heading_quality_baseline.json
```

## Что выдаёт

Отчёт JSON со структурой:

```jsonc
{
  "mode": "manual" | "word-style",
  "documents_evaluated": 12,
  "binary": {                    // heading vs non-heading
    "tp": 145, "fp": 8, "fn": 12, "tn": 5234,
    "precision": 0.948,
    "recall": 0.924,
    "f1": 0.936
  },
  "level": {                     // правильность L1/L2/L3 (только когда обе
                                 //  стороны согласились что это heading)
    "correct": 132,
    "wrong": 13,
    "accuracy": 0.910
  },
  "confusion_levels": {          // куда попадают «промахнувшиеся» уровни
    "1->2": 4, "2->1": 3, "2->3": 5, "3->2": 1
  },
  "per_document": [...]          // детализация по документам — где какие FP/FN
}
```

Числа `binary.precision/recall/f1` и есть то, что вписывается в диплом.

## Как разметить корпус (если решил делать manual mode)

1. Возьми ~10–20 реальных ВКР (своя, друзей, прошлых лет)
2. Для каждого документа открой его и пройди по абзацам:
   - Когда встречаешь заголовок — запиши `paragraph_index` + `level` (1/2/3)
   - Когда встречаешь lead-in (жирный абзац, который похож на заголовок,
     но им не является — «Цели исследования:»), запиши `is_heading: false`
     — это «трудные» отрицательные примеры
3. `paragraph_index` соответствует индексу в `Document.paragraphs`
   python-docx (от 0). Можно посмотреть через короткий скрипт:

```python
from docx import Document as D
doc = D("file.docx")
for i, p in enumerate(doc.paragraphs):
    print(f"{i:3d} | {p.style.name:20s} | {p.text[:80]}")
```

10–20 размеченных документов — это уже статистически значимо для
бакалаврского диплома.
